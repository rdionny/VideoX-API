Apresentacao

A API X e uma API REST construida em Flask que busca dados do XVideos em tempo real e devolve JSON pronto para o seu app Android. Ela foi feita especificamente para esse caso de uso:

  • Grade/lista de videos — titulo, capa, duracao, canal e link da pagina do video.
  • Tela de detalhes — visualizacoes, descricao, data, modelo(s), tags e o link do MP4 para reproducao.
  • Categorias — lista das categorias do site para montar abas/filtros no app.

Como funciona por baixo: cada requisicao sua faz a API abrir a pagina correspondente no site, extrair os dados e devolver um JSON limpo. Ou seja, o conteudo e sempre atual, mas depende da internet e do site estar no ar (por isso existem regras de cache e falhas — veja Limitacoes).

Conteudo adulto: os dados retornados sao majoritariamente 18+. No app, aplique a trava de idade que fizer sentido para voce.

O que voce nao precisa se preocupar

  • Sem chave de API. Nao existe cadastro, token ou rate limit proprio.
  • CORS aberto. Qualquer origem pode chamar — serve ate para prototipos web.
  • Tudo via GET. Nao ha POST, autenticacao nem estado entre chamadas. Cada request e independente.

Comecando passo a passo

  1. Confirme que a API esta viva. Abra /info no navegador ou mande um GET. Deve voltar um JSON com o mapa de endpoints e o codigo HTTP 200. Se aparecer erro de conexao, o servidor esta fora do ar.
  2. Pegue uma lista basica. Chame /videos?source=home&count=5. Voltam 5 itens com slug, titulo, capa_thumb e url_pagina. E o suficiente para montar uma grade na tela inicial.
  3. Monte a grade com o thumbnail pequeno. Use capa_thumb (imagem pequena) nos cards. Use capa (grande) so quando abrir o detalhe. Isso economiza bastante dados moveis.
  4. Ao tocar num card, peca os detalhes. Chame /video/<slug> com o slug que veio na lista. Volta a tela de detalhes com visualizacoes, descricao e o mapa reproducao.
  5. Toque o video. Prefira o campo hls (stream M3U8 adaptativo): ele so e uma URL, e o player escolhe a qualidade sozinho conforme a internet. Se ele vier nulo, caia para o mapa reproducao (MP4). Pede detalhes na hora de tocar — os links expiram em ~1 dia.

Fluxo simplificado do app:

tela inicial  --GET /videos?source=home-->  grade de cards
     (card usa: titulo, capa_thumb, duranca_texto, canal)
  [ toque no card ]
tela de detalhes  --GET /video/<slug>-->  informacoes + reproducao
     (player usa: hls  [ou reproducao["sd"] como fallback])
  [ tocar play ]
player (ExoPlayer / Media3)

GET /videos — listas de videos

E o endpoint principal para grades, buscas e abas. Retorna um conjunto de videos com o minimo necessario para exibir um card na tela.

Parametros (query string)

ParametroTipoPadraoO que faz
source opcionalstringhomeQual pagina buscar. Valores: home, search, category, tag, user.
q obrigatorio*string—Termo de busca, slug da categoria, nome da tag ou usuario. *Obrigatorio quando source e search, category, tag ou user; ignorado em home.
page opcionalint1Numero da pagina (comeca em 1). Ignorado em home.
count opcionalint—Limita quantos videos retornar (corta a lista). Util para pagina controlada no cliente.

Fontes e formatos de chamada

GET /video/<slug> — tela de detalhes

Busca todos os metadados de um video especifico, incluindo o link do MP4 para reproducao. Aceita tres formatos de entrada no caminho, todos equivalentes:

  • /video/olimpkf8bba — slug puro (recomendado)
  • /video/video.olimpkf8bba/x — trecho curto da URL
  • /video/olimpkf8bba/doble_penetration_he_milks_us... — nome grande completo

O parser extrai o slug automaticamente dos tres casos, entao voce pode guardar o url_pagina inteiro que vier da lista e passar direto.

HLS x MP4 — o que usar? O campo hls e a opcao recomendada para um player serio: e o mesmo formato que o proprio site usa, com todas as resolucoes em uma unica playlist. O reproducao (MP4) fica como fallback para players simples que nao falam HLS. Nos dois casos, a qualidade maxima do HLS costuma ser melhor que a do MP4 (MP4 quase sempre sai em 240p/360p; o HLS chega a 1080p).
O mapa reproducao muda de forma. Dependendo do video, voce pode receber uma so chave (sd) ou varias (video_240p, video_360p, ...). No app, percorra o mapa e escolha a melhor chave disponivel — nao faca hard-code de um nome especifico. A URL sempre termina em ?secure=<codigo>,<timestamp> e expira em ~1 dia (veja Limitacoes).

Erros e status HTTP

Todos os erros vem como JSON com um campo erro. Trate esses codigos no app:

StatusCorpoQuando aconteceO que fazer no app
400{"erro":"parametro page invalido"} ou similarq faltando em search/category/tag/user; page/count nao numericos.Bug na sua chamada — revise os parametros.
404{"erro":"nao encontrado"}Slug inexistente (video removido ou typo).Mostre “video indisponivel” e volte a lista.
404{"erro":"rota nao encontrada"}Você chamou uma rota que nao existe (ex.: /videoss).Verifique a URL.
502{"erro":"falha ao buscar do xvideos (http NNN)"}O site respondeu diferente do esperado (429, 5xx, anti-bot).Tente de novo em alguns segundos; mostre estado de recarga.
Dica de UX: em qualquer erro de rede/502, ofereca um botao “tentar de novo”. A API tem cache de 60 s por URL, entao repetir a mesma chamada logo em seguida costuma responder instantaneamente com os dados em cache.

Limitacoes e avisos importantes

O link MP4 expira em ~1 dia

Cada URL de reproducao — seja o MP4 em reproducao ou o M3U8 no campo hls — carrega um codigo ?secure=<codigo>,<timestamp> com validade. O timestamp marca a expiracao: apos ~24 h a URL para de funcionar (o player recebe erro). Regra pratica: chame /video/<slug> no momento em que o usuario toca o play e toque imediatamente em seguida.

Cache de 60 segundos por URL

Internamente a API cacheia cada pagina scrapeada por 60 s. Se voce chamar dois endpoints seguidos que aponte para a mesma pagina do site, o segundo responde na hora usando o cache. Nao altera o contrato JSON — so explica respostas extremamente rapidas logo apos outra.

Retentativa automatica em pagina leve

Quando o site devolve uma pagina “esqueleto” (anti-bot leve, challenge, etc.), a API repete a requisicao uma vez antes de desistir. Isso adiciona alguns segundos em algumas chamadas sem aviso — trate latencia maior como normal.

O site muda de layout (A/B test)

O XVideos testa layouts alternativos entre visitantes. O parser cobre as duas variacoes atuais, mas se o site fizer mudanca mais profunda, algum campo pode vir vazio temporariamente ate o parser ser atualizado. Os campos essenciais (slug, titulo, capa, url_pagina, reproducao) sao priorizados e raros de quebrar.

Visualizacoes usam o numero exibido

O campo visualizacoes reflete exatamente o numero que aparece na pagina do site (que ja vem arredondado por ele). Nao e o contador bruto interno.

Paginacao em home nao existe

source=home retorna apenas a primeira tela do site. Se o app precisa de scroll infinito na aba inicial, use buscas populares ou categorias como continuacao — ou simplesmente limite a uma tela.

source=user e instavel

Paginas de usuario usam JavaScript/XHR no site; a extracao via HTML puro as vezes nao encontra itens. Considere tratar como fonte experimental.

Guia rapido para Android

Tudo que o app precisa e OkHttp (ou Retrofit) + Glide/Coil para imagens + Media3 (ExoPlayer) para o video. Exemplo minimo em Kotlin:

1 · Cliente HTTP e Base URL

val client = OkHttpClient.Builder()
    .connectTimeout(30, TimeUnit.SECONDS)
    .readTimeout(30, TimeUnit.SECONDS)
    .build()

val gson = Gson()
val BASE = "https://seu-tunel.trycloudflare.com"   // troque pela sua Base URL

2 · Buscar a home e montar a grade

data class VideoItem(
    val slug: String, val titulo: String,
    val capa: String, val capa_thumb: String,
    val url_pagina: String,
    val duranca_texto: String, val qualidade: String, val canal: String
)
data class HomeData(val videos: List<VideoItem>)

fun fetchHome(count: Int = 20): List<VideoItem> {
    val url = (BASE + "/videos?source=home&count=" + count)
    val resp = client.newCall(url.toHttpUrlOrNull()!!).execute()
    val body = resp.body!!.string()
    return gson.fromJson(body, HomeData::class.java).videos
}

4 · Tela de detalhes + player Media3

data class Uploader(val nome: String, val usuario: String, val url: String)
data class DetailData(
    val slug: String, val id: Long, val titulo: String,
    val descricao: String?, val url_pagina: String, val capa: String,
    val duranca_seg: Int, val visualizacoes: Int,
    val data_publicacao: String?, val qualidade: String,
    val reproducao: Map<String, String>, val hls: String?,
    val uploader: Uploader,
    val tags: List<String>, val categorias: List<String>
)

fun openDetail(slug: String) {
    scope.launch(Dispatchers.IO) {
        val url = BASE + "/video/" + slug
        val body = client.newCall(url.toHttpUrlOrNull()!).execute().body!!.string()
        val d = gson.fromJson(body, DetailData::class.java)
        withContext(Dispatchers.Main) {
            binding.tvTitle.text = d.titulo
            binding.tvViews.text = d.visualizacoes.toString() + " views"
            binding.tvDesc.text = d.descricao ?: ""
            val player = ExoPlayer.Builder(context).build()
            binding.playerView.player = player
            // 1a opcao: HLS adaptativo - o player troca de qualidade sozinho
            // conforme a rede (o m3u8 pode trazer 250p, 360p, 480p, 720p e 1080p):
            if (d.hls != null) {
                player.setMediaItem(MediaItem.fromUri(d.hls))  // Media3 detecta .m3u8
                player.prepare(); player.play()
            } else {
                // fallback: primeiro MP4 disponivel no mapa
                val mp4 = d.reproducao.values.firstOrNull()
                if (mp4 != null) {
                    player.setMediaItem(MediaItem.fromUri(mp4))
                    player.prepare(); player.play()
                }
            }
        }
    }
}
